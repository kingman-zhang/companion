
# RelationshipAI：关系危机 AI 陪伴产品 — 完整 PRD

---

## 产品简介（TL;DR）

RelationshipAI 是一款定位于 22–38 岁成人，聚焦分手、婚姻冲突、第三者介入等高情绪关系危机场景的 AI 情感陪伴产品。产品愿景覆盖从「情绪失控 → 冷静判断 → 沟通准备 → 过程陪伴 → 放下重建」的全流程；首版 MVP 聚焦「问卷评估 + 情绪聊天 + 消息改写 + 安全拦截」四条核心能力，帮助用户获得即时支持、理性评估和可执行建议，并通过受约束的 LLM 实现精细化输出。

---

## 一、产品目标

### 业务目标

* 验证关系危机陪伴场景的高留存和付费转换潜力
* 形成纯线上、可自主运营的 AI 情感产品，为后续多场景扩展搭建底座
* 在挽回、断联恢复、情绪疏导三方向沉淀标准化核心能力

### 用户目标

* 提供第一时间的情绪安抚支持
* 帮助用户理性判断关系是否值得挽回
* 协助用户改写冲动消息，避免二次伤害
* 引导用户做出「挽回/放下」的可执行选择路径

### 非目标

* 不涉足广义心理健康（如职场、人际冲突）
* 不取代心理/法律/医疗等专业咨询
* 不提供超出关系危机的泛化陪聊

## 二、目标用户与用户故事

### 用户画像

核心用户：22–38 岁，正经历感情破裂、第三者、婚姻危机等情绪高波动时期，手机重度用户，App/Web为主要获取陪伴方式，诉求包括「想挽回」「怕做错」「需要说清」等。

次级用户：尚未决定挽回/放下，有信息表达或体面抽身需求。

### 用户故事

伤心者

* 刚刚分手，希望有渠道讲述痛苦、获得共情回应、情绪不崩溃
* 迫切想知道到底还能不能修复，期望明确信号
* 不敢乱发信息，想让 AI 帮忙润色

挽回者

* 希望拆解出阶段性挽回行动任务，不走极端、不胡乱联系
* 需要每日提醒和目标感

疑虑者

* 怀疑出轨，想风险评估，免得投入更多
* 希望算法直说「适不适合挽回」「是否优先保护自己」

迷茫者

* 想倾诉，分不清现状，急需理清情绪和先后顺序
* 最终希望体面结束，获得恢复生活方法

## 三、产品系统定义

### 系统定义（工程视角）

RelationshipAI 是一个 Web/App 端到端关系危机陪伴系统，基于规则的关系评估和风控架构，通过 API 对接受控 LLM，为用户场景化输出安抚建议、关系状态判断、消息改写与计划任务。

### 系统模块

* 评估模块 Assessment：采集关系快照、规则评分、红黄绿判定
* 聊天模块 Chat：情绪对话、风险标签、微干预及安全检测
* 改写模块 Rewrite：原文输入，多版本风险分级改写
* 计划模块 Plan：阶段性行动规划与任务追踪
* 安全模块 Safety：关键词+分类器双重风险拦截，危机资源推送
* 日志模块 Log：行动与情绪日志、趋势分析与复盘接口

## 五、关系评估系统

### 评分机制

* 六因子加权
  * 关系时长（15）、谁先提出/疏远（10）、联系状态（15）、是否出轨/疑似出轨（20）、是否存在家暴/威胁/控制（25）、事件发生时间（15）
* 评分规则和阈值详见伪代码
* RED override规约（命中家暴、暴力威胁、自伤自杀等严重安全项时直接红，不继续算分）

### 评分分级&置信度

* green: 65分及以上
* yellow: 35-64分
* red: 0-34分或override
* 置信度为规则产物，计算公式为：`confidence = 输入完整率 × 关键项明确度 × 枚举合法率`
* 关键项仅包含 relationship_duration、who_initiated、contact_status、infidelity_present、abuse_flags、time_since_incident
* user_primary_intent 用于后续流向和 CTA，不参与关系得分

### LLM 权限说明

* 只负责llm_reason解释，不能决策分数、颜色、推荐动作
* confidence/level/score全为规则产物

## 六、核心功能规格

### 关系评估

* **输入**：questionnaire_id（关联用户答题单）
* **输出**：assessment_id、score、level、confidence、rule_factors（明细）、llm_reason、recommended_action、created_at
* **处理**：全规则判分→level/置信度→LLM总结理由→recommend动作→返回结构化结果
* **异常**：安全问题直接终止/覆盖红灯，部分信息缺失置信度低要提示

### 情绪急救聊天

* **输入**：session_id/user_id/message
* **输出**：AI回复内容，emotion_label/intensity，微干预（如breathe、delay_send）
* **处理**：先规则安全检测→关键词规则情绪分类→emotion强度超阈发micro-intervention→组装10条上下文喂LLM→输出结果
* **异常/边界**：连续爆表要插入人为介入建议、内容为空等稳定兜底

### 消息改写

* **输入**：user_id/session_id/original_message
* **输出**：3个版本(gentle/direct/brief)、各自风险分级、建议与原因、置信度
* **处理**：安全检测→LLM输出JSON并规则校验→如果风险不符规则覆盖LLM
* **异常/边界**：输入过短/过长直接报错，不合法JSON fallback为本地模板

### 问卷系统

* 见评分模块描述，七题单步显示，提交校验，安全词实时响应

### 行为与恢复计划

* **输入**：user_id/assessment_id
* **输出**：计划id/阶段（stage）/任务（task集合）
* **处理**：评估结果推荐动作定stage→LLM出日计划array→规则补全、边界控制
* **异常**：计划生不出走fallback、7天未完成暂停推进

## 八、AI系统设计

* 什么都不能delegation给LLM决策，所有实际「抉择」/「高敏感」部分必须规则覆盖
* 评估理由chat/prompt明确结构与长度、不得有违规内容
* 改写3选，要求LLM严格JSON输出
* Safety检测为强前置，LLM本身也不许输出鼓励危险、违法、跟踪等内容
* confidence和fallback机制全链路强制

## 九、安全与风控

* 关键词黑白名单+分类器并驱，双线检测
* 自残/家暴/暴力/跟踪>=0.75即安全页
* session全页拦截，不可后退
* 所有事件留审计日志，关键词库热更新
* 用户封锁30分钟冷却，防止绕过

        │           │

**跳转规则说明：**

* P0 → P1：用户点击任意状态卡片
* P1 → P2：7 题全部作答 + 通过校验
* P1 → P8：abuse_flags 包含非 "none" 值
* P2 → P3：用户点击「先处理情绪」
* P2 → P5：level=green 或 yellow 且 intent=reconcile
* P2 → P7：level=red 或 user_primary_intent=letgo
* P3 → P4：用户点击「帮我改写消息」
* P3 → P5：用户点击「开始挽回计划」
* P3 → P7：用户点击「我想放下了」
* P4 → P3：用户点击「继续聊」
* P4 → P5：用户点击「进入挽回计划」
* P5 → P6：计划生成后，用户进入日志记录
* P7 → P6：放下模式启动后，用户进入日志记录
* 任意页 → P8：safety 触发（自残 / 暴力关键词命中）

### P8 · 安全拦截页

**页面目标：** 在检测到高危内容（自残 / 暴力 / 跟踪）后立即终止当前 session，展示固定安全提示和危机资源，禁止用户在当前 session 内继续使用任何功能。

页面特性

| 属性 | 值 |
| --- | --- |
| 是否可关闭 | 否（不可 dismiss，不可后退，不可滑动关闭） |
| 是否覆盖全屏 | 是（z-index 最高，覆盖所有内容） |
| 触发方式 | API 返回 HTTP 451，或 abuse_flags 触发于 P1 问卷页 |
| Session 状态 | 立即标记 session.safety_triggered = true，session 终止 |
| 冷却机制 | 点击「我明白了」后启动 30 分钟冷却计时，期间不可开启新 session |
