# 微信小程序设计与重构规范

本 skill 是团队/项目级别的小程序 UI 设计规范。在为微信小程序写界面、重构界面、做 design review 时，**逐项核对**本 skill 中的规则。

## 何时使用

满足以下任一条件时启用：

- 创建或修改 `.wxml`、`.wxss`、`app.json`、`page.json` 文件
- 设计/重构小程序首页、Tab 页、详情页、表单页
- 需要决定字号、颜色、间距、圆角、阴影等视觉 token
- 需要决定加载反馈、Toast、弹窗、ActionSheet 等交互形式
- 用户描述界面"不专业""不够好看""像草稿"等模糊感受时

## 核心原则（来自张小龙的小程序哲学）

读懂这四条，比记一百条数值更重要：

1. **用完即走，单一路径**。小程序不是 App。每个页面只解决一件事，用户路径必须单一。复合功能堆叠是首屏"不专业"的根源之一。
2. **页面扁平化**。能不跳转就不跳转。跳转层级超过 3 层时应反思架构。
3. **选项 > 输入**。能点选、能拖拽、能预填的，绝不让用户打字。把热门、常用、历史信息前置。
4. **反馈及时**。任何超过 300ms 的操作都要有反馈；任何加载都要有 loading 或骨架屏。"不安全感"会直接劝退用户。

写代码前，先用这四条审视设计稿。

## 尺寸与适配（必读基础）

小程序适配规则与原生 App **完全不同**，写错会全盘崩。

### rpx 单位

- 小程序使用 **rpx** 作为宽度单位，**不要用 px**（除非是边框等需要 1px 精确的场景）。
- 微信渲染时固定视图窗口为 **750rpx 宽**，无论什么设备。
- `rpx = 屏幕宽度 / 750`。换算：iPhone 6（375px 宽）下，1rpx = 0.5px，即 **2rpx = 1px**。
- 适配方式是**等比缩放**，不是 flex 自适应。在大屏上元素会被等比放大。

### 设计画布

- 设计稿用 **375×667**（iPhone SE）或 **375×812**（iPhone X）。
- 开发时开标注工具的 2x 倍率，自动得到 rpx 值。
- 不要用 750 宽画布——会和 WeUI 组件参数对不齐。
- 414×736 是小程序在电脑端启动的默认尺寸，需要桌面端时再考虑。

### 安全区域

- 顶部状态栏 + 胶囊按钮区**不可自定义**，必须预留。
- iPhone X 系列底部要留 `env(safe-area-inset-bottom)` 或固定 68rpx 安全距离。
- 自定义导航栏需读取 `wx.getMenuButtonBoundingClientRect()` 适配胶囊位置。

## 视觉规范（Design Tokens）

完整的 token 表见 `references/design-tokens.wxss`，可直接引入项目。下面是核心心智模型：

### 字号

微信官方推荐字号（pt）：**20 / 18 / 17 / 16 / 14 / 13 / 11**

换算到 rpx（× 2）后小程序常用：

| 用途 | rpx | 场景 |
|---|---|---|
| 巨标题 | 44–48 | 首页 hero 标题、欢迎语 |
| 大标题 | 36 | 页面主标题、模块标题 |
| 标题 | 34 | 列表大项标题、卡片主标题 |
| 正文加强 | 32 | 重要正文、按钮文字 |
| 正文 | 28 | 普通正文、卡片描述 |
| 辅助 | 26 | 次要信息、说明文字 |
| 提示 | 22 | 时间戳、标签、最弱信息 |

**只用 4–5 级**就够了。字号梯队过多是新手最常见错误。

### 字色（基于 WeUI 规范）

| 用途 | 颜色 | 透明度版 |
|---|---|---|
| 主文本 Black | `#000000` 或 `#1A1A1A` | — |
| 强调正文 Semi Black | `#353535` | — |
| 次要文本 Gray | `#888888` | — |
| 辅助文本 Light Gray | `#B2B2B2` | — |
| 链接蓝 | `#576B95` | Press 80% / Disabled 50% |
| 成功绿 | `#09BB07` | 同上 |
| 警告/出错红 | `#E64340` | 同上 |
| 背景 | `#F7F7F7` | 卡片底用 `#FFFFFF` |

**主色应是品牌色，但要符合上面这套灰阶层次**。情感/医疗/儿童类产品避免使用过饱和的红绿；用品牌色 + 中性灰可以撑起 80% 的页面。

### 间距（8 倍数原则）

所有间距用 **8rpx 的倍数**：8 / 16 / 24 / 32 / 48 / 64 / 96。

| 场景 | 推荐值 |
|---|---|
| 页面左右安全 padding | 32rpx |
| 卡片内 padding | 24–32rpx |
| 卡片之间间距 | 24rpx |
| 章节之间间距 | 48rpx |
| 元素间小间距 | 8 / 16rpx |
| 段落行高 | 字号 × 1.5 |

### 圆角

| 元素 | 圆角 |
|---|---|
| 按钮 | 8rpx（方）/ 999rpx（胶囊）|
| 卡片 | 16rpx |
| 大卡片/弹窗 | 24rpx |
| 头像 | 50% |
| 标签/Badge | 8rpx |

### 阴影

小程序里阴影要**很轻**。重阴影是廉价感的来源。

```css
/* 卡片标准阴影 */
box-shadow: 0 2rpx 8rpx rgba(0, 0, 0, 0.04);

/* hover/按下态加深 */
box-shadow: 0 4rpx 16rpx rgba(0, 0, 0, 0.08);

/* 弹窗阴影 */
box-shadow: 0 -4rpx 24rpx rgba(0, 0, 0, 0.08);
```

## 布局层级（WeUI 四层模型）

小程序所有元素只属于这四层，**严格遵守**层级顺序：

1. **Content（内容层，z-index: 1）** — 页面正文，承载主要内容
2. **Navigation（导航层，z-index: 100）** — 顶/底导航，TabBar，固定栏
3. **Mask（蒙层，z-index: 1000）** — 半透明遮罩，配合 Popout 使用，不单独存在
4. **Popout（弹出层，z-index: 1001）** — 弹窗、ActionSheet、Toast、Picker

写 z-index 时直接套这个表，不要随便填 999、9999。

## TabBar 设计

- **数量**：2–5 个，**建议 3–4 个**。5 个会挤，2 个不如不要。
- **高度**：98rpx（不含安全区），加底部安全区后总高约 166rpx。
- **图标**：尺寸 48–56rpx，选中态用**实心**图标，未选用**线性**图标——这是从"业余"跨到"专业"的最便宜的一步。
- **文字**：20–22rpx，选中态用品牌色，未选用 `#999`。
- **首页 Tab 推荐用微信原生底部标签**（`app.json` 的 `tabBar` 配置），自定义 TabBar 仅在有强交互需求（如中间凸起按钮）时使用。

## 加载反馈（绝对不能漏）

任何会让用户等待的地方，**必须**有反馈，**没有反馈 = 卡死**。

| 场景 | 选哪个 |
|---|---|
| 全屏首次加载 | 启动页（微信自动提供品牌 logo + loading）|
| 页面下拉刷新 | `enablePullDownRefresh: true`（微信原生样式）|
| 局部加载（列表加载更多） | Loadmore 组件 + 文字"加载中..." |
| 单个内容块加载 | **骨架屏**（最优解，避免布局跳动）|
| 提交操作进行中 | 按钮置 disabled + "提交中..." 文字 |
| 网络请求 | `wx.showLoading` 模态加载（**慎用**，会锁屏）|
| 操作成功 1.5s 后消失 | `wx.showToast({ icon: 'success' })` |
| 操作失败需用户知晓 | `wx.showModal` 模态对话框 |

**不要在同一页同时跑两个 loading 动画**。

## 反馈样式选择

| 情况 | 用什么 |
|---|---|
| 轻量成功提示（点赞、收藏） | Toast 图标型，1.5s 自动消失 |
| 轻量文字解释（"已是最新"） | Toast 文字型 |
| 用户必须知晓的结果或下一步指引 | 模态对话框（Modal） |
| 多个并列操作选择（分享到、删除/编辑） | ActionSheet |
| 单项选择（时间、地区） | Picker |
| 流程终结（支付完成、提交成功） | 结果页（独立页面，不是弹窗） |
| 表单出错 | 顶部告知错误原因 + 字段下方红字标注 |

**禁止**用 Toast 提示错误——Toast 一闪而过，用户错过就找不回。

## 重构 checklist

接到"这个小程序不够专业"的需求时，按顺序检查：

### Level 1 — 基础规范（不达标就别谈"美"）

- [ ] 用 rpx 不是 px
- [ ] 间距全部是 8 的倍数
- [ ] 字号层级 ≤ 5 级
- [ ] 颜色梯队遵循"主/次/辅助/提示"四档
- [ ] 圆角统一（按钮、卡片、头像各自统一）
- [ ] 阴影轻、统一

### Level 2 — 信息架构

- [ ] 每个页面只承担一个核心任务
- [ ] 跳转深度 ≤ 3 层
- [ ] 首屏第一眼能看懂"这是什么、我能做什么"
- [ ] 减少输入，提供预设选项 / 历史记录 / 推荐
- [ ] 关键操作（CTA）唯一且醒目，颜色与品牌色一致

### Level 3 — 反馈与交互

- [ ] 所有加载有反馈（骨架屏 > spinner > 文字）
- [ ] 所有点击有 hover/active 态（`hover-class` 或 CSS `:active`）
- [ ] 操作成功/失败有明确反馈
- [ ] 表单错误就近提示，不用 Toast
- [ ] 长内容有分页或加载更多，不要无限滚动到底

### Level 4 — 细节专业度

- [ ] TabBar 选中态用实心图标
- [ ] 卡片有微阴影 + 微圆角
- [ ] hero 卡片（首屏第一张大卡）做差异化设计，不和后面卡片同质
- [ ] 列表项有合适的"按下"反馈
- [ ] 空状态有友好的插画或文案，不是"暂无数据"
- [ ] 顶部状态栏区域适配胶囊按钮
- [ ] iPhone X 系列底部安全区适配

### Level 5 — 品牌一致性

- [ ] 主色只有 1 个，辅助色 ≤ 2 个
- [ ] 所有页面使用同一套 design tokens（来自 `references/design-tokens.wxss`）
- [ ] 字体粗细只用 regular / medium / semibold 三档，不要用 bold + 多种字号叠加
- [ ] 插画/图标风格统一（要么全线性、要么全面性、要么全 3D）

## 文件结构建议

```
project/
├── app.wxss            # 全局样式，import design-tokens
├── styles/
│   ├── tokens.wxss     # design tokens（颜色/字号/间距/圆角）
│   └── mixins.wxss     # 通用 mixin（卡片、按钮、阴影）
├── components/         # 自定义组件
│   ├── card/
│   ├── empty/
│   └── skeleton/
└── pages/
```

## 何时打破规则

规则不是宪法。如果你在做的是：

- **品牌活动小程序**（如新春活动、品牌联动）— 视觉可以更大胆、动效更多、装饰元素更重，但**仍然遵守 token 系统**，只是 token 数值会更激进。
- **儿童/老人向产品** — 字号整体上调 2 级，TabBar 高度上调到 120rpx。
- **工具类小程序** — 信息密度可以更高，但仍要遵守"用完即走"。

打破规则前，确认是基于用户研究而不是个人偏好。
