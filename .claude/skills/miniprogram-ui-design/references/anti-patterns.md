# 小程序常见反模式与修复

> 这份清单来自实战。每个反模式都标了**症状 → 原因 → 修复**。

## 反模式 1：用 px 而不是 rpx

**症状**：在 iPhone 12 上看起来正常，到 Pro Max 上字偏小、间距变挤；或反过来。

**原因**：写了 `font-size: 14px;` 这种写法。小程序的 px 是物理像素，不随屏宽缩放。

**修复**：全部换成 rpx。Vim 一键：`:%s/\(\d\+\)px/\12rpx/g`（粗略，慎用）。手动检查：边框可保留 `1rpx` 或 `2rpx`，但其他都用 rpx。

---

## 反模式 2：间距随手填数字

**症状**：卡片间距一会儿 20rpx、一会儿 26rpx，整体节奏混乱。

**原因**：写样式时凭感觉填数字。

**修复**：建立 `--md-space-*` 变量，**只**用 8 的倍数。如果某处觉得"必须 18rpx 才好看"，几乎一定是别处出错了。

---

## 反模式 3：字号层级超过 5 级

**症状**：列表标题 30rpx，副标题 26rpx，描述 24rpx，时间 22rpx，标签 20rpx，价格 32rpx，原价 28rpx……眼睛累，找不到重点。

**原因**：想让所有信息都被看到。

**修复**：信息层级要靠**字号 + 字重 + 颜色**三维度建立，不只是字号。例：
- 价格 36rpx semibold #1A1A1A
- 标题 28rpx medium #1A1A1A
- 描述 26rpx regular #888888
- 标签 22rpx regular #B2B2B2

四档足够建立清晰层级。

---

## 反模式 4：阴影过重

**症状**：每个卡片都飘起来，像 PPT，廉价。

**原因**：抄了 Material Design 的强阴影，但小程序的微信白底场景应该用极轻阴影。

**修复**：阴影 alpha 不超过 0.08，模糊半径不超过 16rpx：
```css
box-shadow: 0 2rpx 8rpx rgba(0, 0, 0, 0.04);
```

---

## 反模式 5：场景卡片同质化

**症状**：5 张卡片一模一样的样式，眼睛扫过去无记忆点。

**原因**：用 wx:for 循环渲染相同 template。

**修复**：
1. 第一张做成 hero 卡（1.5x 高 + CTA 按钮），后续为小卡。
2. 每张卡左侧加圆形图标区，背景色用 token 中的浅色变体。
3. 用 emoji 作为占位图标（成本 0，效果立竿见影）。

---

## 反模式 6：按钮在没输入时显示灰色

**症状**：输入框旁有个灰色"提交"按钮，看起来像坏了。

**原因**：把"禁用"做得太显眼。

**修复**两选一：
- **方案 A**：未输入时按钮**完全隐藏**或半透明 0.3。一旦有内容，淡入显示为品牌色。
- **方案 B**：按钮始终显示为品牌色，但点击时弹 Toast"请先输入..."。

灰色 disabled 是 desktop UI 思维，小程序应避免。

---

## 反模式 7：用 Toast 报错

**症状**：表单填错，Toast 弹"邮箱格式错误"1.5 秒消失。用户：什么错？哪一项错？

**原因**：Toast 一闪而过，错误信息一定要持续显示。

**修复**：
- 字段下方红字提示 + 输入框红边
- 顶部 banner 汇总所有错误
- 提交按钮置灰直到错误修复

---

## 反模式 8：无限滚动列表无骨架屏

**症状**：列表加载时一片白，加载完突然弹出，整页跳动。

**原因**：偷懒没做骨架屏。

**修复**：用 `<view class="skeleton">` 配 CSS 渐变动画占位。骨架结构和真实内容**完全一致**（占位高度一样、占位条数一样），加载完替换内容时不会跳动。

---

## 反模式 9：TabBar 用 emoji 当图标

**症状**：底部 Tab 一排 emoji，安卓和 iOS 渲染不同，整体跑形。

**原因**：图省事。

**修复**：用 SVG 转 PNG（@2x @3x 三套），放 assets/tabbar/。线性版本 + 实心版本各一套。`app.json` 配置：

```json
"tabBar": {
  "color": "#999999",
  "selectedColor": "#E91E63",
  "list": [{
    "iconPath": "assets/tabbar/home.png",
    "selectedIconPath": "assets/tabbar/home-active.png"
  }]
}
```

如果实在没设计师，用 [iconfont.cn](https://iconfont.cn) 的开源线性图标包，免费且一致。

---

## 反模式 10：把 App 那套照搬过来

**症状**：小程序首页堆了 8 个入口、3 个 banner、2 个推荐位、1 个直播挂件。

**原因**：产品经理拿着 App 的设计稿要求"做得一样"。

**修复**：小程序的**核心心智**是用完即走、单一路径。砍掉 50% 入口，留下用户最常用的 3 个核心动作。如果产品经理坚持，给他读张小龙关于小程序的演讲。

---

## 反模式 11：没有空状态

**症状**：用户第一次进来，列表是空的，整页空白，疑惑这是不是坏了。

**原因**：开发只考虑"有数据"的情况。

**修复**：每个列表页都设计 3 个状态：
1. **加载中** — 骨架屏
2. **有数据** — 正常渲染
3. **空状态** — 插画 + 友好文案 + 引导 CTA（"还没有记录，去添加第一条"）
4. **错误** — 重试按钮

---

## 反模式 12：自定义导航栏不适配胶囊按钮

**症状**：自定义导航栏覆盖到了右上角胶囊按钮区，或留白对不齐。

**原因**：没读 `wx.getMenuButtonBoundingClientRect()`。

**修复**：在 app.js onLaunch 中获取胶囊位置，存到 globalData，导航栏组件根据这个值动态计算 padding：

```javascript
const menuButton = wx.getMenuButtonBoundingClientRect();
const statusBarHeight = wx.getSystemInfoSync().statusBarHeight;
const navBarHeight = (menuButton.top - statusBarHeight) * 2 + menuButton.height;
```

---

## 反模式 13：跳转太深

**症状**：用户操作 3 次后已经迷失，不知道在哪里。

**原因**：把 App 的多级菜单原样搬过来。

**修复**：
- 用底部抽屉（Half-screen Dialog）代替二级页面
- 用 Tab 切换代替页面跳转
- 用展开/折叠代替"查看详情"页面

小程序的导航成本远高于 App，能不跳就不跳。

---

## 反模式 14：滚动卡顿

**症状**：长列表滚动掉帧。

**原因**：用 `<view>` 渲染长列表，没用 `<scroll-view>`，或用了但没开 `type="list"`。

**修复**：
```html
<scroll-view 
  scroll-y 
  type="list" 
  enhanced 
  bounces="{{false}}"
  enable-back-to-top
>
  <view wx:for="{{items}}" wx:key="id">...</view>
</scroll-view>
```

数据超过 50 条时考虑用 `recycle-view`（虚拟滚动）。

---

## 反模式 15：所有页面 background 不一致

**症状**：A 页背景白，B 页背景灰，跳来跳去像换了 App。

**原因**：没在 app.wxss 设全局 background。

**修复**：在 app.wxss 设：
```css
page {
  background-color: var(--md-bg-page);
}
```

仅在个别页面（如详情页）需要纯白背景时单独覆盖。
